## 4. Deterministic Host Identity Verification

In prior milestones, repeated local audits of an identical host produced different `AssetId`s because `openaudit-cli audit local` initialized a random `OrganizationId` on each invocation.

In M2.2, standalone local audits bind to a deterministic default organization ID (`OrganizationId::from_seed(b"openaudit:local:default-org")`), deriving `AssetId` deterministically from `/etc/machine-id`:

- **Scenario S00 asset.id:** `16070aa6-edd6-5bde-877f-c71906871072`
- **Scenario S00b asset.id:** `16070aa6-edd6-5bde-877f-c71906871072`
- **Determinism match:** Identical SHA-256 seed derived across separate container executions.
- **Stable asset identity:** **YES**

## 6. Key Architectural Takeaways

1. **Ubuntu 24.04 UsrMerge Resolution:**  
   SUID/SGID scanning required normalizing symlinked directories (`/bin` -> `/usr/bin`, `/sbin` -> `/usr/sbin`) to prevent duplicate findings and false positives for standard system binaries.
2. **Nftables Default Policy Semantics:**  
   Distinguishing active firewall rules from an empty table with `policy accept;` ensures OpenAudit accurately reports inactive packet filters without false negatives.
3. **Container-Isolated Procfs Simulation:**  
   Hermetic bind-mount testing enabled realistic sysctl inspection in disposable test environments without requiring host kernel reconfiguration.
